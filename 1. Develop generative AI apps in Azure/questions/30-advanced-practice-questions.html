1.1 Plan and Prepare

3 questions

1. Changing knowledge, stable writing style

A manufacturer needs a support application that answers from approved warranty policies, which change daily. Answers must cite the current policy and use a consistent company tone. A prompt with a few examples already meets the tone requirement. The team wants the least complex design that stays current without repeated model training.

Which design should you choose?

  1. Fine-tune on each day's policies and rely on the model to remember source citations.
  2. Use RAG over a maintained policy index, supplying source metadata and the tested tone instructions at generation time.
  3. Put every policy into a long-lived conversation once and reuse that conversation indefinitely.
  4. Fine-tune for tone first, then use the model's pretrained knowledge for policy answers.
Answer

Answer: B

Why: The unresolved problem is current, attributable knowledge, not learned writing behavior. RAG supplies current evidence; the proven prompt handles tone.

  • A: Daily retraining adds operational cost and does not provide reliable source-level citations.
  • C: Conversation state is bounded and becomes stale; it is not an updateable knowledge index.
  • D: Fine-tuning an already-satisfied behavior does not solve access to current private policies.

Remember: Grounding supports citations; the application must still validate sources and unsupported claims.

2. Development access must not become production access

A team prototypes a generative application with developer credentials. Production must use an application identity, prohibit stored keys, and prevent developers from accidentally querying production customer data while testing. The team can provision distinct development and production resources.

Which environment design best meets all requirements?

  1. Share the production resource, place keys in environment variables, and give test prompts a development prefix.
  2. Use one service principal with the same client secret and broad permissions in both environments.
  3. Keep separate projects but grant every developer and application identity access to all connected data sources.
  4. Use separate environment resources/connections, managed identity for the production app, and environment-specific least-privilege role assignments.
Answer

Answer: D

Why: Identity, authorization, and environment boundaries must be enforced independently; resource names or prompt labels are not isolation controls.

  • A: Stores keys and relies on a convention rather than access control.
  • B: Violates the secretless requirement and creates cross-environment access.
  • C: Separate projects alone do not constrain shared downstream permissions.

3. A leaderboard is not a deployment decision

A model leads a public benchmark, but the application needs a specific input modality, an approved processing location, and a p95 response time below two seconds. Before approving the architecture, the team must establish both feasibility and actual workload fitness.

Choose TWO checks that together address these requirements.

  1. Verify the model's required modality, context limits, deployment availability, quota/capacity, and processing-location constraints.
  2. Choose the highest benchmark score and assume the application's latency will follow the same ranking.
  3. Run representative task and load evaluations for quality, safety, latency, and cost in a compliant deployment.
  4. Replace application evaluations with confirmation that the model accepts the request format.
  5. Use the Azure resource's storage location as proof of where every deployment type processes inference.
Answer

Answer: A, C

Why: Capability and compliance checks eliminate infeasible candidates; workload evaluations establish whether a feasible candidate actually meets the thresholds.

  • B: A public benchmark is not a workload-specific latency or quality guarantee.
  • D: Request acceptance establishes API compatibility, not acceptable outcomes.
  • E: Processing geography depends on deployment type, not only the resource's storage location.

Why: Medium satisfies both hard thresholds at $0.48, less than the qualifying router's $0.57.

  • B: Most accurate, but exceeds the latency limit.

5. Processing location includes overflow

A bank permits inference only within one named Azure region. It has a predictable baseline and variable bursts, and wants reserved capacity for the baseline with consumption-based overflow. The model supports both regional deployment types. The application will explicitly route overflow requests.

Which deployment pair meets the location requirement?

  1. Regional Provisioned and Regional Standard, both in the approved region.
  2. Data Zone Provisioned and Data Zone Standard in a data zone containing the region.
  3. Regional Provisioned for normal traffic and Global Standard for overflow.
  4. Global Provisioned and Global Standard resources created in the approved region.
Answer

Answer: A

Why: Every permitted execution path must remain region-bound. Provisioned handles the baseline; regional Standard is the compliant overflow choice among these options.

  • B: A data zone may contain several regions.
  • C: The overflow path breaks the same rule that the baseline satisfies.
  • D: Resource creation location does not restrict Global inference to that region.

Validate capacity and latency on both paths; this design does not guarantee that overflow capacity is always available.

6. Isolate bulk inference from interactive quota

A retailer runs an interactive assistant on a Standard deployment. It also needs to generate descriptions for 300,000 archived products. The archive workload can complete asynchronously, has no hard deadline, and permits global processing. The team wants lower inference cost without consuming the interactive deployment's real-time token quota.

Which option should you choose for the archive workload?

  1. Standard calls on the same deployment, submitted through a client-side batch loop.
  2. The same Standard deployment with streaming enabled for each archived product.
  3. Provisioned throughput purchased solely to avoid submitting requests asynchronously.
  4. Global Batch with its asynchronous processing and separate enqueued-token quota.
Answer

Answer: D

Why: Service-side Batch matches the latency tolerance, cost objective, and quota separation.

  • A: A client loop does not turn Standard requests into the Batch service or separate their quota.
  • B: Streaming changes response delivery, not quota accounting.
  • C: Adds reserved-capacity cost without the stated real-time requirement.

Batch turnaround is a target, not a hard completion guarantee.

7. More retries make throttling worse

A Python application receives 429 responses during short bursts. The SDK retries internally, while an outer application loop retries each failed SDK call three more times. Traces show synchronized retries, and responses include a retry-delay header. The allocated quota supports the measured steady workload.

Which change best addresses the demonstrated failure?

  1. Increase retries in both layers so each request has more chances to succeed.
  2. Use one bounded retry layer, honor the service delay, use backoff with jitter when needed, and smooth request bursts.
  3. Reduce temperature and retain the same nested retry schedule.
  4. Increase concurrency to drain the local queue before the next rate-limit window.
Answer

Answer: B

Why: Remove retry multiplication and synchronized load. Use either the configured SDK retry behavior or a controlled outer policy, not accidental stacking.

  • A: Multiplies attempts and can prolong throttling.
  • C: Generation variability is not the observed rate-limit problem.
  • D: Increases burst pressure rather than respecting backpressure.

Surface retry exhaustion explicitly. If sustained demand exceeds quota, capacity planning is still required.

4 questions

8. Project operations are not model inference

A Python service must enumerate a Foundry project's connections and call a deployed model through the Responses API. The developer has a project endpoint and Microsoft Entra credentials but is trying to perform both operations through a standalone inference client.

Which client arrangement should you use?

  1. Use a standalone inference client at the project endpoint for both connection enumeration and generation.
  2. Use DefaultAzureCredential alone for both operations, without a service client.
  3. Create AIProjectClient with the project endpoint and credential; use get_openai_client() for supported model operations and target the deployment name.
  4. Use the Azure AI Search client to enumerate Foundry connections and send Responses requests.
Answer

Answer: C

Why: Project management and model inference are different API surfaces. The project SDK provides the supported bridge to an authenticated OpenAI client.

  • A: An inference client does not become a project-management client merely by changing its endpoint.
  • B: A credential obtains authentication material; it is not a service API client.
  • D: The Search client targets another service.

Match the installed SDK/API generation; do not mix legacy connection-string examples with current endpoint-based setup.

9. Ordering: streaming is not a complete response

An application streams a structured model response for progress feedback. It must persist a completed business result only after generation finishes and validation succeeds. A dropped connection or refusal must produce an explicit failure/review state, not a fabricated result.

Order these stages:

  1. Validate the complete structured output and its business invariants.
  2. Start the request using a supported streaming API.
  3. Inspect terminal status; branch explicitly on refusal, interruption, or incomplete generation.
  4. Persist the validated result on success, otherwise the explicit failure/review state.
  5. Accumulate the relevant output deltas without treating individual chunks as complete JSON.

Which sequence is correct for the successful path, with failure branches handled at their detection point?

  1. 2 → 5 → 3 → 1 → 4
  2. 2 → 1 → 5 → 4 → 3
  3. 2 → 5 → 4 → 3 → 1
  4. 1 → 2 → 5 → 3 → 4
Answer

Answer: A

Why: Collect output, establish completion, validate, then commit the business result. Streaming improves perceived responsiveness but is not a completion guarantee.

  • B: Tries to validate before collecting the output and persists before checking terminal status.
  • C: Commits unvalidated, potentially incomplete content.
  • D: Cannot validate a generated response before the request exists.

Use the events and completion/refusal indicators defined by the chosen API; event names differ between APIs.

10. Local success does not prove production access

A Foundry app works locally under a developer's identity. Its Azure-hosted deployment must authenticate without stored keys or client secrets and receive only the permissions needed for project/model operations. Network access is already verified. The team must not copy the developer's login state into production.

Choose TWO actions that together implement the production authentication and authorization design.

  1. Copy the developer's cached token into the deployment artifact.
  2. Enable/configure the production managed identity and use an appropriate Azure Identity credential for the service clients.
  3. Grant subscription-wide Owner to the developer because local execution already succeeds.
  4. Reuse a project endpoint as the credential because the URL uniquely identifies the project.
  5. Assign the production identity the required least-privilege roles at the relevant project/resource scopes.
Answer

Answer: B, E

Why: The production workload needs its own identity and its own authorization. When using DefaultAzureCredential, verify which identity is selected in each environment.

  • A: Copies user authentication state and does not establish a safe workload identity.
  • C: Changes the wrong principal and grants excessive permissions.
  • D: An endpoint identifies a destination, not caller authority.

11. Schema compliance is not business correctness

An app extracts invoice data with a model/API supporting structured outputs. The workflow needs mandatory fields, an approved currency enum, and a total equal to the sum of line items. Schema-valid results have occasionally contained incorrect totals. Refused or incomplete responses must not reach the accounting system.

Which implementation satisfies the complete contract?

  1. Enable JSON mode and accept every parseable response.
  2. Request the schema in the prompt and use low temperature instead of validation.
  3. Use structured outputs and submit every schema-valid result directly to accounting.
  4. Use supported schema-constrained output, then validate arithmetic/business rules and explicitly handle refusals, incomplete outputs, and validation failures.
Answer

Answer: D

Why: Syntax, schema, business correctness, and exceptional outcomes are separate checks.

  • A: JSON mode does not enforce the required schema or arithmetic.
  • B: A prompt and low temperature are not an output contract.
  • C: Correct field types do not prove that a total was calculated correctly.

1.4 Get Started with Prompt Flow

3 questions

12. Put deterministic rules outside the LLM node

A Prompt Flow application retrieves discount policy text and asks an LLM to draft a quotation. The discount amount must follow an exact rounding rule and an authoritative pricing function. Tests show occasional arithmetic errors when those rules are implemented only as prompt instructions.

Which flow design should you use?

  1. Repeat the rounding rule several times in the prompt and allow the model to calculate the final price.
  2. Use a Python tool node to call/implement the authoritative pricing logic, bind its validated result into the LLM prompt, and validate the exposed flow output.
  3. Use an evaluation flow as the production price calculator after the quotation has already been sent.
  4. Replace the pricing function with a larger model and remove the deterministic checks.
Answer

Answer: B

Why: Prompt Flow can compose Python and LLM tools. Deterministic computation belongs in code; language generation explains the verified result rather than authorizing a new price.

  • A: Repetition does not guarantee exact computation.
  • C: Evaluation measures results; running it after publication does not prevent an incorrect quote.
  • D: Model size does not turn probabilistic arithmetic into an enforced business rule.

13. Perfect evaluation caused by answer leakage

A batch dataset contains question and expected_answer. A flow accepts query and produces answer. Scores jump unexpectedly after someone maps both dataset columns into the generation prompt. The test is intended to measure answering without access to the reference answer.

Which mapping should you use?

  1. Map expected_answer into both the generation prompt and the evaluation target.
  2. Map the flow's generated answer back into query and use the original question as ground truth.
  3. Map question to the generation flow's query; pass the run's generated answer and the separate reference answer to the evaluation flow.
  4. Remove the reference answers from evaluation and report only whether the generation run completed.
Answer

Answer: C

Why: Generation and evaluation require different inputs. Reference answers belong to the evaluator, not to a generation task designed to work without them.

  • A: Preserves the leakage and inflates the result.
  • B: Reverses the semantics of inputs and reference data.
  • D: Avoids measuring answer quality instead of fixing the mapping.

Inspect sample-level inputs and outputs as well as the aggregate score.

14. Compare prompts without confounding or leaking secrets

A team has two alternative prompts for one LLM node. It wants to compare them fairly on the same dataset and promote the selected flow to another workspace. Credentials differ by environment and must not be embedded in prompt templates or source-controlled flow files.

Choose TWO practices that meet these requirements.

  1. Use LLM-node prompt variants and comparable batch runs with the same dataset, model configuration, and evaluation criteria.
  2. Evaluate each prompt on a different random subset and change the model at the same time.
  3. Insert credentials directly into the prompt template so each variant is self-contained.
  4. Use named Prompt Flow connections for service configuration and bind/provision the appropriate connections and permissions in each environment.
  5. Select the prompt producing the shortest average response without assessing whether it still answers correctly.
Answer

Answer: A, D

Why: Controlled variants isolate the prompt change; connections keep service configuration and secret handling outside prompt text. Promotion still requires correct target-environment bindings and access.

  • B: Confounds prompt, dataset, and model effects.
  • C: Exposes credentials to source control and potentially model inputs.
  • E: Optimizes a proxy without a quality gate.

1.5 Develop a RAG-based Solution

5 questions

Shared case study for Q15-19: A multi-tenant policy assistant uses Azure AI Search. Source PDFs include tables and exceptions spanning page boundaries. Chunks must retain report/page references and tenant/group access metadata. A trusted backend resolves current user permissions; this design uses application-enforced security filters. Policies change daily, and both exact policy identifiers and everyday-language questions must work. Document and query embeddings must remain compatible.

15. Ordering: preserve evidence through ingestion and retrieval

The team needs an end-to-end pipeline in which vector fields represent the final chunks and no unauthorized chunk enters model context. Consider these stages:

  1. Generate an answer from eligible retrieved evidence and validate its source citations.
  2. Extract content/layout and associate source/page and access metadata.
  3. Generate embeddings for the finalized chunks.
  4. Retrieve with compatible query embeddings and enforced permission filters; optionally rerank.
  5. Create coherent chunks while preserving their source and access metadata.
  6. Index chunk text, embeddings, and metadata with appropriate mappings/projections.

Which order satisfies the dependencies?

  1. 2 → 3 → 5 → 6 → 4 → 1
  2. 2 → 5 → 6 → 4 → 3 → 1
  3. 2 → 5 → 3 → 6 → 1 → 4
  4. 2 → 5 → 3 → 6 → 4 → 1
Answer

Answer: D

Why: Extract, form evidence-preserving chunks, embed those chunks, index, perform authorized retrieval, then generate.

  • A: Embeds before the final chunk units exist.
  • B: Attempts vector retrieval before the necessary chunk vectors have been produced and indexed.
  • C: Generates before retrieval and access filtering.

Source metadata is part of the pipeline, not something to guess from the generated answer.

16. Retrieval finds the rule but loses its exception

OCR is accurate, but fixed-size chunks separate policy limits from exceptions and drop table headings. Answers cite the correct report yet sometimes apply the wrong limit. Increasing the number of retrieved chunks adds unrelated text without consistently restoring the missing relationship.

Which change most directly addresses the root cause?

  1. Use layout/section-aware chunking, preserve headings and table context, apply useful overlap where needed, and evaluate retrieval plus answers again.
  2. Change only the chat model's temperature while retaining the broken chunk boundaries.
  3. Remove exceptions from the index so the model receives a simpler rule.
  4. Fine-tune the generation model on previous answers without correcting the ingestion pipeline.
Answer

Answer: A

Why: Relevant words are present, but their semantic relationships were lost during preparation. Repair the evidence units rather than hide the symptom.

  • B: Does not restore missing contextual relationships.
  • C: Deletes evidence necessary for correct decisions.
  • D: Leaves the root cause and risks learning outdated policy behavior.

No chunk size or overlap is universally best; evaluate with representative tables, cross-page exceptions, and citation requirements.

17. Equal vector dimensions, incompatible meaning

The index contains vectors produced by embedding model A. A developer changes only query vectorization to model B. Both outputs have 1,536 dimensions, so requests succeed, but relevance drops. Text, filters, and chunking are unchanged.

Which correction should you make?

  1. Keep model B and increase neighbor count because equal vector length proves compatibility.
  2. Pad or truncate every query vector to 1,536 dimensions.
  3. Restore a compatible query configuration; if migrating to B, regenerate document vectors in a compatible field/index and evaluate before switching both sides.
  4. Rely on semantic ranker to permanently compensate for the incompatible embedding spaces.
Answer

Answer: C

Why: Dimensionality is a shape constraint, not proof that two models encode comparable coordinates. Document and query embeddings need a compatible embedding space/configuration.

  • A: More neighbors do not repair semantic incompatibility.
  • B: The vectors already have matching lengths; padding/truncation does not align their meanings.
  • D: Reranking may improve surviving candidates but cannot fix first-stage vector retrieval.

18. A cache can bypass an otherwise secure retriever

The assistant's service identity can query every tenant. A browser supplies a tenant field, and the application caches answers by question text alone. Access membership can change. Both retrieval and cached answers must prevent disclosure to an unauthorized user.

Choose TWO controls that address both paths.

  1. Derive current tenant/group scope from validated identity data in the backend and enforce it on every retrieval.
  2. Trust the browser's tenant value if it matches a tenant name mentioned in the question.
  3. Keep the global answer cache but remove citations when a different user receives the answer.
  4. Ask the model to filter restricted facts after loading cached or retrieved content.
  5. Scope cache reuse to an appropriate authorization context and source validity, rechecking or invalidating entries when access or underlying policy changes.
Answer

Answer: A, E

Why: A cache is another content-delivery path. Correct retrieval filtering does not protect answers reused across users or after access revocation.

  • B: Uses attacker-controlled claims rather than trusted identity.
  • C: Removing a citation does not remove the confidential answer content.
  • D: Enforces access too late and makes the model a security boundary.

A tenant-only cache key can still be too broad when users within that tenant have different access.

19. Candidates exist, but context selection is wrong

A hybrid query returns 50 candidate passages containing the correct explanation. The application sends the first three directly to the model, and those three often omit the best passage. The team wants a language-understanding ranking stage before constructing the limited generation context.

Which change should it make?

  1. Increase the generation model's output-token limit while using the same first three passages.
  2. Apply semantic ranking to the retrieved candidates before selecting the passages for the generation prompt.
  3. Shorten the indexer schedule even though the indexed policy text is current.
  4. Apply semantic ranking only after truncating the candidate list to the same first three passages.
Answer

Answer: B

Why: The evidence is in the candidate set; the failure occurs when ordering and selecting context. Rerank before throwing useful candidates away.

  • A: Longer answers do not add missing evidence.
  • C: Freshness is not the observed failure.
  • D: Cannot recover a useful passage already removed by truncation.

1.6 Fine-tune a Language Model

3 questions

20. Specialize behavior without freezing knowledge

A legal application already retrieves the correct current clauses. Its remaining problem is consistently producing a specialized analysis style. Prompt iterations and schema constraints have not met the quality target. The team has many high-quality approved input/output examples. The source regulations continue to change.

Which approach should it evaluate next?

  1. Fine-tune on the current regulations and remove retrieval entirely.
  2. Increase only the number of retrieved passages even though evidence coverage is already sufficient.
  3. Use JSON mode alone to learn the specialist analysis style.
  4. Fine-tune a supported model on curated examples of the desired behavior, retain RAG for current clauses, and evaluate against the existing baseline.
Answer

Answer: D

Why: Stable behavior specialization and changing knowledge are different needs. Fine-tuning is justified here by failed simpler approaches and suitable examples, not as the default first step.

  • A: Treats model weights as an updateable regulatory database.
  • B: Targets an evidence problem the scenario says is already solved.
  • C: Valid JSON does not teach specialist reasoning or style.

Improvement is not guaranteed; preserve an independent quality and safety evaluation set.

22. More examples can mean less useful data

A supervised fine-tuning dataset contains exported support conversations. Several conversations are duplicated with minor wording changes; some assistant replies are incorrect, and some contain personal data. A random row split puts variants of the same customer case into both training and validation.

Which preparation strategy should you choose?

  1. Keep all examples because dataset size outweighs correctness and duplication.
  2. Remove only exact byte-identical duplicates and keep random row splitting.
  3. Curate approved answers, remove or appropriately sanitize sensitive data, deduplicate related cases, split by case/source group, and validate the required conversational JSONL format.
  4. Train on the validation set too, then measure quality using the training service's success status.
Answer

Answer: C

Why: Label quality, privacy, formatting, and leakage control all matter. Related-case splitting prevents near-duplicates from inflating validation results.

  • A: Incorrect targets teach unwanted behavior; volume is not a substitute for quality.
  • B: Leaves semantic duplicates and related-case leakage.
  • D: Eliminates independent evaluation; successful training is not proof of a useful model.

1.7 Implement Responsible Generative AI

4 questions

23. Grounded content can still contain hostile instructions

A summarization application retrieves external reports. A report containing no violent or sexual content embeds instructions telling the model to disregard its summary task and disclose unrelated context. Existing harmful-content filters do not flag it. The team wants a control targeted at this failure, without treating retrieved text as trusted instructions.

Which change should it make?

  1. Lower only the threshold for violence detection.
  2. Add Prompt Shields for document attacks and preserve the separation between untrusted source content and application instructions.
  3. Use a groundedness score as proof that the retrieved document is authorized to redefine the task.
  4. Fine-tune on the hostile report so that the model recognizes it as company data.
Answer

Answer: B

Why: This is an indirect prompt-injection attempt in grounding content, not necessarily a harmful-content-category violation.

  • A: Tunes the wrong detection category.
  • C: Supporting a claim with a source does not make the source a trusted instruction authority.
  • D: Adds training work without establishing a runtime trust boundary.

Detection is defense in depth, not a guarantee. Minimize available context and independently enforce access restrictions.

24. Redacted model input, unredacted telemetry

A trusted ingestion component may receive raw customer messages for PII detection. The summarization model, analytics store, and operational logs may receive only redacted content. A prototype redacts the model prompt but logs the raw HTTP body and exception payload first.

Choose TWO controls that implement the complete data-handling requirement.

  1. Use PII detection/redaction inside the trusted ingestion boundary before passing content downstream.
  2. Ask the summarizer to omit personal details while continuing to send it the raw message.
  3. Keep raw logs and delete sensitive values after the nightly analytics job.
  4. Configure telemetry and exception paths to exclude raw content, retaining only permitted redacted data and necessary diagnostic metadata.
  5. Turn on model content filtering and assume it automatically redacts the application's HTTP logs.
Answer

Answer: A, D

Why: Model prompts, storage, traces, and errors are separate disclosure paths. Preprocessing and safe observability must enforce the same boundary.

  • B: Disclosure has already occurred when raw text reaches the model.
  • C: Violates the policy before cleanup.
  • E: A model filter does not control application logging.

Evaluate detector misses and retention controls; automated redaction cannot guarantee removal of every sensitive value.

25. A safety block is not a transient capacity error

A generative application receives an explicit content-filter refusal or filtered completion. Its generic retry handler treats every missing answer as a transient service failure, repeatedly resubmitting the same request. Product policy requires safe handling without relaxing configured protections.

Which response strategy should you implement?

  1. Retry until one response gets through, then present it as the normal result.
  2. Automatically lower filter thresholds only for requests that have already failed.
  3. Substitute a fabricated successful answer so the UI does not show an error.
  4. Distinguish safety outcomes from retryable transport/rate-limit failures, present an appropriate safe explanation or allowed alternative, and record only permitted diagnostic metadata.
Answer

Answer: D

Why: Different failure classes need different handling. A safety outcome is not fixed by blind retries or bypassing the protection.

  • A: Wastes requests and attempts to route around the safety decision.
  • B: Silently weakens the required policy.
  • C: Invents a result instead of accurately reporting the outcome.

Do not expose raw blocked content or misleadingly report a refused response as a completed task.

26. A strong average hides an unacceptable cohort

A multilingual generative assistant improves average task success from 91% to 95%. A predeclared release rule requires at least 90% success for each supported language. One low-volume language falls from 90% to 74%, but its small sample share barely affects the average.

Which release decision should you make?

  1. Hold release for the affected scope, investigate with representative language-specific evaluations, remediate, and rerun every required quality/safety gate.
  2. Release because the weighted average improved by four percentage points.
  3. Remove that language from the evaluation report while continuing to advertise support.
  4. Increase temperature for all requests and assume the additional variability addresses the cohort gap.
Answer

Answer: A

Why: The per-language gate is a hard requirement. Aggregate improvement cannot cancel a failing supported cohort.

  • B: Ignores a declared release condition.
  • C: Hides the failure rather than resolving the user impact.
  • D: Changes a parameter without evidence that it fixes the issue.

A scope restriction requires an explicit product decision and accurate user communication, not silent metric exclusion.

1.8 Evaluate Generative AI Performance

4 questions

27. Every claim is supported, but the question is unanswered

A user asks when a warranty exception applies. The retrieved context contains the answer. The model instead summarizes the general warranty duration. Every statement it makes is supported by the context, and its writing is clear, so groundedness and fluency scores are high.

Which evaluation dimension most directly exposes the remaining failure?

  1. Fluency, because unsupported statements are the main issue.
  2. Groundedness alone, because any supported response must also answer the question.
  3. Relevance, assessing whether the response addresses the user's actual request.
  4. Token usage, because a shorter response is necessarily more relevant.
Answer

Answer: C

Why: The problem is answering the wrong aspect of the question, not inventing unsupported claims.

  • A: The response is already fluent; fluency does not establish task completion.
  • B: Groundedness and relevance measure different properties.
  • D: Output length is not a correctness metric.

If an expected answer is available, a completeness check can additionally assess omitted required facts.

28. Better relevance cannot buy a failed grounding gate

29. Debug the retrieval stage and watch the deployed system

A RAG app's offline answer quality falls after changing retrieval settings. The team has query-to-document relevance labels and needs to identify the retrieval regression. After a fix, it also needs to detect future changes in real traffic without storing unrestricted user content.

Choose TWO complementary evaluation practices.

  1. Use a Document Retrieval evaluator against the labeled query/document relevance data, inspecting per-query failures as well as aggregate metrics.
  2. Evaluate only generated-text fluency because polished answers prove retrieval is correct.
  3. Use training loss from an unrelated fine-tuning job as the retrieval metric.
  4. Treat one successful offline run as proof that the deployed app will not drift.
  5. Combine privacy-controlled production tracing/monitoring with sampled quality and safety evaluations, alerting on relevant regressions and reviewing affected cases.
Answer

Answer: A, E

Why: Labeled retrieval evaluation isolates a stage-specific regression; controlled production evaluation detects changes that a fixed offline set may miss.

  • B: Fluent text can be generated from irrelevant or incomplete evidence.
  • C: Training loss measures a different process.
  • D: Production data, indexes, model versions, and user behavior can change.

Use permissions, retention controls, and redaction for any evaluation samples; observability is not permission to retain all content.

30. The model is fast, but the application is slow

A model deployment's latency and token usage are stable, but the application p95 rises after a retrieval change. The request path includes query embedding, search, reranking, prompt assembly, and generation. Operations needs to locate the delay and correlate it with answer quality without logging raw documents.

Which measurement design should you implement?

  1. Monitor only the model deployment's average inference latency.
  2. Record Azure resource-management events as a substitute for request-level spans.
  3. Measure only final response length and assume larger outputs caused the regression.
  4. Capture correlated application/dependency spans with safe metadata, export to Application Insights, and associate permitted evaluation results with request/run identifiers.
Answer

Answer: D

Why: End-to-end observability exposes which stage is slow and allows quality investigations without requiring raw source text in logs.

  • A: Omits most of the application path and hides tail behavior in an average.
  • B: Management-plane events are not a trace of request execution.
  • C: Substitutes a weak proxy for direct timing evidence.

Instrument relevant stages and review per-run breakdowns before changing the model or buying additional capacity.
